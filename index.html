Approach

How I work

Four things I hold to, in roughly the order they come up in a project.

Data

Most of the problem is in the data

Most of the performance I have gained came from understanding the data itself: how the missingness arose, whether the encoding is consistent across sources, and whether the sample represents the population being predicted for. A more complex model usually belongs after that work rather than instead of it.

Data

Define the question before building anything

What is being predicted, at what moment it is predicted, and who will act differently because of it. Until those three are settled, a higher metric does not mean much.

Models

Model choice needs a control

Same data, same split, from logistic regression through gradient boosting. What is worth reporting is which family wins, under what conditions, and by how much, rather than which one I happened to use.

LLM

An LLM's output needs a traceable basis

Retrieval grounding, structured output, and cited sources all serve the same purpose: an answer can be traced back to where it came from instead of only sounding credible. I hold LLM components to the same evaluation standard as any other model in the pipeline.

Machine Learning-Based Model for Postoperative Stroke Prediction in Coronary Artery Disease

Pan, H. · Chen, S. · Pishgar, E. · Alaei, K. · Placencia, G. · Pishgar, M.

Stroke after coronary revascularization is rare enough that a model can score well by predicting it never happens. I completed the CITI training and data use agreement myself, wrote the BigQuery SQL that joined 53 MIMIC-IV tables into one record per patient, and applied the inclusion criteria that narrowed 364,627 unique patients to a cohort of 7,023. The analysis handles missingness, encoding, scaling, and correlation filtering, selects features with LASSO, corrects the class imbalance, tunes XGBoost, CatBoost, SVM, and logistic regression, and reports SHAP attributions. Best test AUROC was 0.855, with bootstrap confidence intervals, calibration curves, and sensitivity and specificity reported per model rather than behind a single headline number. I wrote the methods section and produced every table and figure.

Research Assistant

LIME is the Language, Intelligence, and Model Evaluation/Ethics lab. The problem was binary risk classification on a psychosocial survey: 200 respondents, 200 variables, free-text answers included. Small enough that every point estimate needs an interval next to it.

  • Established logistic regression and XGBoost baselines first. They came out weak and unstable, 0.45 recall and 0.54 precision with wide k-fold cross-validated 95% confidence intervals, so the ceiling of the classical route was clear before anything else was tried.

  • Tested zero-shot, few-shot, chain-of-thought, and structured-output variants and kept the negative result: few-shot examples inflated already long inputs and degraded performance, so zero-shot won.
  • Built the reproducible, Git-versioned Python pipelines for data preparation, training, checkpoint evaluation, and error analysis, run on Google Cloud virtual machines and USC's CARC cluster.

Decision Analysis LLM

An agentic decision-analysis assistant. You describe a decision in plain language; it frames the problem, asks only the questions that still matter, elicits preferences through concrete either-or choices rather than 1 to 10 ratings, and routes to the analysis model that fits the decision type: MAUT with Monte Carlo for discrete choice, expected utility with a prospect-style value function for uncertain bets, and a bounded optimizer for allocation.

The division of labor is strict. The LLM handles judgment, meaning framing, proposing alternatives, and critiquing the analysis, while every number comes from deterministic, seed-stable Python. Value-of-information analysis identifies which unresolved uncertainty is worth checking before committing, and each report records the verbatim request, the full Q&A, and per-item provenance, so the result can be audited rather than taken on trust. It runs as a deployed service, containerized with Docker and served with FastAPI over WebSocket on Railway, so you can try it rather than read about it.
